# `MaskRLE` encoding

This is the exact run-length encoding the server emits for segmentation masks, as documented
(in our own words, for this kit) from the server's mask codec. It is a small, dependency-free,
JSON-friendly scheme — deliberately not tied to any third-party RLE format — but the underlying
idea (alternating run lengths) is the same one COCO-style RLE uses.

## Shape on the wire

```ts
interface MaskRLE {
  size: [number, number]; // [H, W] — mask height then width, in pixels
  counts: number[];       // alternating run lengths, see below
  order: 'C';             // always "C" (row-major); reserved for a possible future variant
}
```

## The encoding rule

1. The mask is a 2D boolean grid, `H` rows by `W` columns. `True` = pixel is part of the
   segmented object; `False` = it isn't.
2. Flatten the grid **row-major** ("C" order): row 0 left-to-right, then row 1, and so on. This
   is the same order you'd get from nested loops `for r in range(H): for c in range(W): ...`,
   or from `numpy.ravel(order="C")`.
3. Walk the flattened sequence and record the length of each maximal run of consecutive-equal
   values. `counts` is exactly that list of run lengths, in order.
4. **Runs always alternate, and the sequence always starts with a `False` run** — even if the
   mask's first pixel is `True`. If the mask actually starts `True`, the first entry in `counts`
   is `0` (a zero-length "False" run), so the alternation rule stays fixed and simple: **the
   value of run `i` is `False` when `i` is even, `True` when `i` is odd** (0-indexed). A decoder
   never needs to inspect the mask to know which runs are "on" — only the index parity.
5. Consequences of the rule:
   - `counts` can be empty only when `H * W == 0` (a zero-dimension mask).
   - `sum(counts)` must always equal exactly `H * W`. This is the cheapest validity check and
     the one this kit's fixtures exercise (see the invalid fixture below).
   - `counts.length` can be even or odd — an odd length just means the mask ends on a `True`
     run.

## Worked examples

### Example A — starts `False`

Mask (`H=2, W=3`):

```
0 0 1
1 1 0
```

Flattened row-major: `0, 0, 1, 1, 1, 0`.

Runs: `False×2`, `True×3`, `False×1`.

```json
{ "size": [2, 3], "counts": [2, 3, 1], "order": "C" }
```

Check: `sum([2, 3, 1]) == 6 == 2 * 3`. ✓. Run 0 (`False`) is even-indexed, run 1 (`True`) is
odd-indexed, run 2 (`False`) is even-indexed — matches the parity rule.

### Example B — starts `True`

Mask (`H=2, W=2`):

```
1 0
0 0
```

Flattened: `1, 0, 0, 0`. The sequence starts `True`, so we lead with a zero-length `False` run:

```json
{ "size": [2, 2], "counts": [0, 1, 3], "order": "C" }
```

Check: `sum([0, 1, 3]) == 4 == 2 * 2`. ✓. Decoding: run 0 = `False`×0 (nothing), run 1 = `True`×1
(pixel `[0,0]`), run 2 = `False`×3 (pixels `[0,1]`, `[1,0]`, `[1,1]`).

### Example C — all-`False` ("empty") mask

Mask (`H=3, W=3`), nothing detected:

```
0 0 0
0 0 0
0 0 0
```

```json
{ "size": [3, 3], "counts": [9], "order": "C" }
```

A single `False` run covering the whole frame. This kit's `fixtures/empty_64x64.json` is this
case at a larger size (one run of `4096`).

### Example D — invalid (rejects, doesn't silently decode)

Take Example A's encoding but shorten the last run so it no longer covers the frame:

```json
{ "size": [2, 3], "counts": [2, 3, 0], "order": "C" }
```

`sum([2, 3, 0]) == 5 != 6 == 2 * 3`. A decoder must **reject** this — it must not return a
5-pixel or zero-padded 6-pixel buffer, because that would silently misrepresent the mask.
`fixtures/invalid_counts_mismatch_8x8.json` in this kit is exactly this failure mode (a
truncated final run) at `8x8`, generated by `scripts/make_fixtures.py`.

## Decoding algorithm (reference, in words)

```
given size = [H, W], counts = [c0, c1, c2, ...]:
  if H * W == 0: return an empty (0-length) buffer
  allocate flat = zero-filled buffer of length H * W
  pos = 0
  value = False
  for each c in counts:
    if value is True and c > 0:
      set flat[pos .. pos+c) = 1
    pos += c
    value = not value
  if pos != H * W:
    reject — invalid encoding
  reshape flat (row-major) into H x W if you need a 2D view; a flat buffer is also a valid
  decode target (see src/maskOverlay.ts's chosen return type)
```

## Validity checklist for `decodeMaskRle`

Reject (don't decode) when any of these hold:
- `size` is not a 2-element array of finite numbers.
- `counts` is not an array, or contains a non-finite / non-integer-coercible entry.
- `order` is not exactly `"C"`.
- `sum(counts) != size[0] * size[1]`.

The protocol's `isMaskRle` guard (see `src/protocolTypes.ts`) checks the *shape* (types, array
lengths, `order === 'C'`) but deliberately does **not** check the `sum(counts) == H*W` invariant —
that's a decode-time concern, not a wire-shape concern, which is exactly the gap
`decodeMaskRle` needs to close. `fixtures/invalid_counts_mismatch_8x8.json` passes `isMaskRle`
(right shape, right types) but must still be rejected at decode time.
