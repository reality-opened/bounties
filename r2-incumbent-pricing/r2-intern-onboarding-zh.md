## Part 1 · 任务操作手册：给行业定价做一张"底价表"

### 一、这个任务是干什么的（先看懂再动手）

先讲清楚 OpenReality 做什么。

**背景：机器人是在"虚拟世界"里学本领的。** 训练一个机器人（机械臂、机器狗、人形机器人）叠衣服、搬箱子，不能直接在真实世界里练——练一百万次，东西早摔坏了。所以行业的通行做法是先在电脑里的**仿真环境**（simulation，就是一个物理规律逼真的 3D 虚拟世界）里练，练好了再搬到真机上。

**问题：这些虚拟世界从哪来？** 现在主要靠 3D 美术师一间房一间房手工建模，又贵又慢；或者用昂贵的激光扫描设备扫描。这是整个机器人行业公认的瓶颈。

**OpenReality 做的事：把"建虚拟世界"变成"拍一段视频"。** 拿任何拍摄设备——手机、装在机器狗背上的摄像头、机械臂上的相机、无人机——对着一个真实场景走一圈拍下来，我们的软件自动把它变成 3D 场景，并且直接输出成机器人训练软件能用的格式（行业里叫 **real-to-sim**，"从现实到仿真"）。一句话：**我们把真实世界变成机器人的练功房。**

那这个任务和你有什么关系？我们要决定先把这个能力卖给谁，判断标准之一是：**现在的人们为了得到同样的东西（可用的 3D 场景、机器人训练数据），都在花多少钱？** 如果现有的方案很贵、我们的成本很低，那个方向就值得进。

你的任务就是把"他们现在花多少钱"查清楚，做成一张表。这张表会直接用于公司决策，所以有一条铁律：**表里的每一个数字，都必须能指出"我是在哪个网页看到的"。** 查不到来源的数字，宁可不写。

### 二、名词小词典（后面会反复出现的词）

| 词 | 意思 |
|---|---|
| 行业方向（vertical） | 一个细分市场。比如"游戏 3D 素材"是一个方向，"机器人训练数据"是另一个 |
| 现有厂商（incumbent） | 已经在这个方向里卖同类东西的公司 |
| 仿真环境（simulation environment） | 电脑里物理规律逼真的 3D 虚拟世界，机器人在里面练习 |
| real-to-sim | "从现实到仿真"：把真实场景变成仿真环境，我们做的就是这个 |
| 3D 资产（asset） | 可以买卖的 3D 模型文件：一把椅子、一间厨房、一整个仓库场景都算 |
| 遥操作（teleoperation / teleop） | 人远程操纵机器人做示范动作，录下来当机器人的"教材"，按小时收费很贵 |
| 计价单位（unit） | 这个价格买到的是什么：一次扫描 / 一平方英尺 / 一次检查 / 一个场景 / 一小时飞行 / 一个账号一年 |
| 买家画像（buyer context） | 谁在付这笔钱：住宅业主还是商业地产？保险公司的核保部门还是理赔部门？大型总包还是区域小包？同一个服务卖给不同买家，价格可以差好几倍，所以这一列必须填 |
| 采购记录（procurement record） | 政府机关、公立学校花钱买东西的公开记录。**这是最好的价格来源**，因为那是真实成交价，不是标价 |
| 材料包（kit） | 我们发给你的那个文件夹，里面有格式说明和参考文档 |
| 快照（snapshot） | 网页的"存档照片"。网页以后可能改版或删除，快照能证明"我看到的时候它是这样写的" |
| PR（Pull Request） | 在 GitHub 上交作业的动作，意思是"请求把我的修改合并进去" |

### 三、你要查的三个行业方向（已确定，可以直接开工）

这三个方向不是三个不相干的市场，而是**同一个问题的三个答案**：一个搞"具身智能 / 物理 AI"（physical AI，
指真实世界里能动的机器人，区别于只在屏幕里说话的 AI）的团队，今天想让机器人有一个逼真的练功房，
有三条路可走——买现成的、去现场扫一个、或者干脆跳过场景直接买训练数据。你要查的是**这三条路各自
今天要花多少钱**，所以请把它们当成互相替代的方案来比价。

> 1. **买现成的：仿真用 3D 场景怎么买、多少钱**
>    机器人公司和游戏公司需要现成的 3D 场景（一间厨房、一个仓库、一条街道）。查两类价格：
>    (a) 3D 素材商店里"整个场景/环境"类商品的标价（这类网站明码标价，最好查——代表：TurboSquid、Sketchfab、Fab/Unreal 商店；重点留意标注了 "SimReady" 或 "USD" 的商品，那是专门给仿真用的）；
>    (b) 定制建模的报价：请 3D 美术师/外包工作室按需求做一个场景收多少钱（自由职业平台的报价页、工作室官网、论坛里的行价讨论）。
>
> 2. **去现场扫一个：传统 3D 扫描服务多少钱**
>    我们的"用手机拍视频"替代的是什么？是激光扫描公司上门扫一栋楼的服务（关键词：laser scanning、reality capture、scan-to-BIM；代表公司：GPRS、各地测绘/扫描服务商）。他们通常按面积或按次报价。**这一条是我们成本优势的对照基准**——查清楚了，才知道我们到底便宜多少倍。
>
> 3. **跳过场景直接买数据：机器人训练数据多少钱**
>    机器人公司花钱买"教材"：遥操作示范数据（按小时收费）、数据标注服务（按条/按小时）、合成数据平台（按张/按场景）。代表公司：Scale AI、Surge AI、各种 robotics data collection 服务商。这类价格官网常常不标（"价格面议"），采购记录和用户自述是主要来源。
>
> （加分项，做不完不勉强：**国防/训练仿真采购**。美国军方买"仿真训练环境"的合同金额全部公开可查，搜 `synthetic training environment contract award` 或到 SBIR 官网查中标记录。）

目标：三个方向加起来，**至少 15 行**有来源的定价数据。

**注意三个方向的查法完全不同**：方向 1（3D 场景）主要靠素材商店的商品标价，最好查；方向 2（扫描服务）主要靠政府采购记录，得会挖 PDF 附件；方向 3（训练数据）两样都少，官网基本只写"价格面议"，多半只能靠买家自述——**所以方向 3 查到的行数少是正常的，别硬凑**。与其编三行凑数，不如在总结里写清楚"这个方向的价格根本查不到、我试过 ABC 方法"，那对我们更有用。

### 四、表格怎么填：一行一个价格

**直接写进材料包里的 `materials/starter-benchmarks.md`，追加在示例行下面。** 不要另外开 Excel——那份文件的列顺序就是验收标准，格式转换过程中最容易出错。它是 Markdown 表格，一行就是一个 `|` 分隔的文本行，照着上面的示例行抄格式就行。

十列，顺序不能变：

| 列名（英文表头） | 填什么 | 示例（数字是编的，仅演示格式） |
|---|---|---|
| vertical（行业方向） | 上面三个方向中的哪一个。**必须用这三个固定写法之一**，不要自己改措辞，否则表格没法按方向分组：`Sim-ready 3D assets`（方向 1）/ `Reality capture`（方向 2）/ `Robot training data`（方向 3） | Sim-ready 3D assets |
| company（公司） | 卖东西的公司/平台名 | TurboSquid |
| service（产品/服务） | 具体哪个商品或服务，要具体 | 完整厨房场景 3D 模型，含家具，SimReady 标注 |
| unit（计价单位） | 这个价格买到的是什么 | per asset（一个场景买断） |
| price（价格） | 数字 + 货币 | $249 USD |
| buyer context（买家画像） | 谁在付这笔钱 | 独立游戏工作室 / 机器人实验室，自助下单 |
| source (URL)（来源链接） | 你实际打开的那个网页的完整网址 | https://…（商品页） |
| access date（查看日期） | 你是哪天打开这个网页的 | 2026-08-02 |
| confidence（可信度） | 四选一，见下面第五节 | [verified] |
| notes（备注） | **快照链接（必填）** + 任何需要说明的事 | 快照：https://web.archive.org/…；同类厨房场景价格 $50–$800，本行取中位价位商品；不含物理属性 |

关于两个日期：`access date` 填**你打开网页那天**，不是网页上写的发布日期。如果来源写明了价格的生效时间（比如合同签订日期、费率表的版本年份），把它写进 notes。

### 五、"可信度"怎么选（四选一）

这四个标签决定了这个数字后面能怎么用，所以别凭感觉填。**只有 `[verified]` 的行，以后才能拿去算"买家一年花多少钱"这类账**；其他三档是有用的情报，但单独一行撑不起一个结论。

- **`[verified]`（你亲眼在原始来源上看到了这个数字）**
  你自己打开了那个页面，数字明明白白写在上面，而且是最近 180 天内看的。算数的来源：公司官网定价页、**政府采购合同的附件（费率表/报价表）**、GSA CALC+ 的费率查询结果、行业协会某个具体年份的费率报告、素材商店的商品标价页。
  *（注意：政府采购记录属于 `[verified]`，而且是里面最硬的一种——那是真实成交价。）*

- **`[reported]`（有人说他付过这个钱，但你看不到原始单据）**
  论坛/Reddit 帖子、G2 或 Capterra 的用户评价、领英评论、行业媒体文章里引用的价格。**备注里必须写清楚：谁说的、在哪说的。** 在"价格全部面议"的行业（比如机器人训练数据），这可能是唯一能拿到的信号，所以要写进表里——但把它当线索：能顺藤摸瓜找到原始来源、升级成 `[verified]` 的话，一定去做。

- **`[inferred]`（你自己算出来的）**
  网页没直接写单价，你根据别的数字推算的。例：公司年报说"1 万个客户、年收入 500 万美元"，你算出平均每客户每年约 $500。
  **备注里必须写清完整算式和每个输入数字的出处**，让别人能照着重算一遍。

- **`[example]`（材料包里预置的示例行）**
  只是格式参考，永远不能当证据引用。那三行请原样保留，不要改、不要删。

**四档都放不进去的数字，就不要写进表里。** 一个来源不清的数字比没有数字更糟糕——因为它看起来像是能引用的。

### 六、去哪里找价格（按产出效率排序）

搜索时**用英文关键词**，这些公司和查询网站几乎全是美国的，中文关键词基本搜不到。
详细操作看材料包里的 `sourcing-cheatsheet.md`（那份写了每个网站怎么用）。

1. **政府和学校的公开采购记录**（最高产，对应上面方向 3）
   美国的政府机构、公立学区花钱买东西必须公开记录。关键点：**采购公告页面通常只写合同总额，真正的"单价"在附件 PDF 里**（费率表、报价表）——一定要把 PDF 下下来看。
   - 搜索法：Google 搜 `"公司名" purchase order`、`"公司名" contract price`、`"公司名" board approved`、`"in the amount of" 公司名`
   - 专门的网站：FPDS（联邦合同）、USAspending.gov、各州的 "checkbook" 支付公开网站

2. **GSA CALC+ 费率查询**
   美国政府采购服务的官方工具（buy.gsa.gov），能查到测绘、扫描类工种的中标时薪。按工种搜（surveyor、photogrammetrist）。

3. **公司官网的 Pricing（定价）页**
   最直接。打开官网找 "Pricing" 菜单。两个坑：写 "Contact sales"（联系销售）意思是这页拿不到数字，别硬猜，换方法；写 "from $99"（99 美元起）见下面第七节第 2 条。

4. **素材商店 / 经销商的商品标价**（对应上面方向 1，是这个方向的主力来源，不是备选）
   直接看商品页标价。注意筛"整个场景/环境"类商品，不要单件道具。**备注里记下同类商品的价格区间**——一个 $249 的厨房场景说明不了什么，"40 个同类厨房场景在 $50–$800 之间"才说明问题。

5. **客户案例（case study）和新闻稿**
   有时会提到合同金额。如果你拿合同总额除以数量得到单价，那是 `[inferred]`，算式写备注。

6. **用户评价网站和论坛**
   G2.com、Capterra.com（软件评价网站，类似"软件版大众点评"）、Reddit（美国版贴吧）。用户有时会说自己付了多少钱 → 记为 `[reported]`，备注写"用户自述 + 帖子链接"。

7. **上市公司年报**
   适合推算平均价（`[inferred]`）。这个最难、产出最低，放最后，做不了也没关系。

**查不到也是结果。** 如果某家公司完全不公开价格、也找不到采购记录，把这件事明确写进总结里，不要跳过、更不要猜一个数字。"这个方向的价格根本查不到"本身就是有价值的情报——它意味着后面的人得先去要报价单才能往下算。

### 七、三条铁律（违反会被打回重做）

1. **每个网页都要存快照。** 定价页经常改版，快照证明你看到时的样子。操作：
   - 打开 https://web.archive.org
   - 把定价页的网址粘贴进 "Save Page Now"（保存网页）框，点保存
   - 把生成的快照链接复制到你那行的 **notes** 列
   - **边查边存**，不要留到最后——留到最后的时候，有些页面已经改了
2. **"起价"不等于价格。** 网页写 "from $99/月"（99 美元起）时：price 列写 `$99/mo`，confidence 选 `[verified]`，但 notes 里必须写"起价，实际可能更高"。绝不能把它当成"就是 99"。同理，"最高不超过 X" 是天花板，也要注明。
3. **只追加，不修改。** 这张表是"只能往下加"的。发现某个价格变了、或者找到了更好的来源，**在下面新加一行**，不要去改老的那行（在新行的 notes 里写"取代 2026-XX-XX 那一行"）。老行的历史本身有用——它解释了当时的备忘录是基于什么假设写的。

另外一条不算铁律但要知道的规矩：**遇到价格区间，照原样记区间，不要自己取个中间值。** 后面拿这个区间去算账时，我们统一取**低端**——把买家的花费往低了算，等于把我们的价格优势往小了说，宁可保守。

### 八、工作节奏（预计 1.5–2 个工作日）

1. **第 1 步（30 分钟）**：读材料包里的 `benchmark-row-format-and-sourcing-rules.md`（格式和可信度标签，最重要）和 `sourcing-cheatsheet.md`（去哪找）。看不懂的词回到本文第二节查。
2. **第 2 步（半天）**：先只做 **5 行**，发给任务负责人。这一步是校准——确认你对格式和"可信度"的理解是对的，避免方向错了白做。
3. **第 3 步（一天）**：按反馈补完剩下的 10+ 行，边查边追加进 `starter-benchmarks.md`，边查边存快照。
4. **第 4 步（30 分钟）**：把 `materials/findings-summary-template.md` 复制成 `materials/findings-summary.md` 填一遍（每节几句话就行）：三个行业里，哪个的定价看起来最贵、最有降价空间？哪个已经打价格战了？**哪些公司你完全查不到价格、你试过什么方法**——这一节别省，它能让下一个人不用重走你的死胡同。
5. **第 5 步**：提交 PR（表格 + 总结一起交）。

**卡住了怎么办：同一个问题卡住超过 30 分钟，直接来问，不要自己耗着。** 每天发一句进度就行，不用写正式汇报。

### 九、怎么算"完成"（验收标准）

以 README 的 Acceptance criteria 为准，核心是这几条：

- 至少 15 行，覆盖分配给你的三个行业方向，列的顺序和 `starter-benchmarks.md` 完全一致
- 每一行十列都填了，每一行的 notes 里都有 archive.org 快照链接
- 每一行都有来源链接，点开（或看快照）就能看到那个数字
- `[inferred]` 的行写了完整算式和输入出处；`[reported]` 的行写了谁说的、在哪说的
- "起价"都在备注里标注了；价格区间保留成区间
- 三行 `[example]` 原样保留；没有任何一行老数据被改写
- 交了填好的 `findings-summary.md`，里面包含"查不到价格的公司"清单
- 没有任何"凭印象写的"数字

### 十、规矩（必须遵守）

- 材料包和你做的表都是**公司内部资料**，不要转发给别人
- 开始交作业之前，要签一份简单的知识产权协议（意思是：你为这个任务做的成果归公司；任务负责人会发给你）
- 只写查到的数字；拿不准就在 notes 里写"拿不准"以及为什么，**诚实比好看重要**
- 如果你在我们发的材料里看到疑似客户名字或密码钥匙之类的东西：停下来告诉我们。那是我们的失误，发现了算你的功劳

## Part 2 · 技术学习路线（边做边学）

你说想在做调研的同时学技术——我们的任务板就是按这个设计的：像游戏关卡一样，**每一关只需要上一关的技能，再加一点点新东西**。不需要"先学好了再开始"，检验标准就一条：能不能独立做完下一关的任务。

（下面提到的任务需要单独申请，每个任务是一个独立的仓库，认领后才会开权限。）

### 第 0 关 · 本周顺便学（约 3–4 小时）

**学什么：Git 和 GitHub。**
- Git：程序员用来管理文件版本的工具——每次修改都有记录，可以随时回到任何一个历史版本，多人改同一堆文件也不会乱。
- GitHub：一个存放和协作这些文件的网站（可以理解成"程序员的云盘 + 协作平台"）。你以后交任务就通过它，交一次任务的动作叫 PR（Pull Request，"请求把我的修改合并进来"）。
- 资源：GitHub 官网的 "Hello World" 新手教程（跟着点一遍就懂）；想深入再看免费电子书 Pro Git 前 3 章。
- 顺便学 Markdown：一种用纯文本写出标题、表格、列表的写法（你现在读的这份文档、以及你要填的那张表，都是用它写的），10 分钟就会。

**这一关就是 R2 本身要用到的**——你交这个任务的时候正好练一遍。

### 第 1 关 · Python 入门（1–2 周业余时间）

- Python：目前最流行、对新手最友好的编程语言。
- 目标：能写一个几十行的小程序，做到"读一个文件 → 处理里面的文字 → 写出一个新文件"。
- 资源：《Automate the Boring Stuff with Python》（免费在线书，中文名《Python 编程快速上手》，专为零基础写的）。
- 这期间可以接 **R3 或 R4**（调研公开数据集的任务）：还是查资料性质，但会逼你学会读懂开源许可证（license，即"这份数据允许怎么用"的法律条款）和数据格式——这已经是技术能力的一半。

### 第 2 关 · 第一个真正的技术任务：T1

T1 是专门给"第一次写工具的人"设计的任务：写一个小程序，检查一种记录相机运动轨迹的文本文件（叫 TUM 格式）有没有格式错误。

新东西只有四样，材料包里都有说明和例子：
- 怎么按格式解析一个文本文件
- 四元数（quaternion）：用 4 个数字表示"物体朝向"的数学写法——你不用懂原理，只需要会检查"这 4 个数字的平方和开根号是不是等于 1"
- pytest：Python 里写"自动检查自己程序对不对"的工具
- 把程序打包成别人一条命令就能安装的形式

做完 T1，你就完成了从"查资料"到"写程序"的跨越。

### 第 3 关 · numpy 和一点 3D 基础（2–3 周）

- numpy：Python 里做数字计算的工具库，处理成千上万个数字像处理一个数字一样快。
- 学一点 3D 常识：什么是点云（point cloud，用几十万个带颜色的空间点拼出的 3D 模型——我们产品的输出就是它）、什么是旋转和平移。
- 对应任务：T5（生成测试用的假数据）或 T2（检查 3D 模型文件的工具）。
